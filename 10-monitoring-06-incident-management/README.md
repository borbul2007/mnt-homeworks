# Домашнее задание к занятию 17 «Инцидент-менеджмент»

## Задание

Составьте постмортем на основе реального сбоя системы GitHub в 2018 году.

Информацию о сбое можно изучить по ссылкам ниже:

* [краткое описание на русском языке](https://habr.com/ru/post/427301/);
* [развёрнутое описание на английском языке](https://github.blog/2018-10-30-oct21-post-incident-analysis/).


**Краткое описание:**	некорректное отображение информации на веб-сайте GitHub.\
**Предшествующие события:**	плановые работы по замене вышедшего из строя оптического оборудования.\
**Причина инциндента:**	потеря связи между ЦОД.\
**Воздействие:** пользоватеоли столкнулись с тем, что после нескольких попыток создания Issue и записи комментариев к уже существующим — запись/комментарий визуально отображались, а после перезагрузки — пропадали.\
**Обнаружение:** проблема была зафиксированина дежурными инженерами поддержки в 2018 Октябрь 21 22:54 UTC.\
**Реакция:** связь между ЦОД была восстановлена за 43 секунды. Восстановление качества обслуживания было устранено за 24 часа и 11 минут.\
**Восстановление:** было воплнено восстановление данных из резервной копии и осуществлена репликация между ЦОД.

**Таймлайн:**\
  2018 Октябрь 21 22:52 UTC - после потери связи между ЦОД произошел сбой в процессе работы репликации.\
  2018 Октябрь 21 22:54 UTC - система мониторинга зафиксировала многочисленные сбои. Дежурные инженеры выяснили несогласованность топологии репликации БД, которая включала только сервера из одного ЦОД.\
  2018 Октябрь 21 23:07 UTC - заблокированы внутренние инструменты развертывания, чтобы предотвратить внесение каких-либо дополнительных изменений. Зарегистрирован инцидент.\
  2018 Октябрь 21 23:13 UTC - инженреры БД приступили к анализу и составлению плана восстановления работоспособности сервиса.\
  2018 Октябрь 21 23:19 UTC - приостановлены выполнения заданий записи метаданных, приостановлена доставка вебхуков и сборки GitHub Pages.\
  2018 Октябрь 22 00:05 UTC - принято решение о восстановлении из резервных копий и синхронизация реплик между ЦОД.\
  2018 Октябрь 22 00:41 UTC - запущен процесс восстановления для всех затронутых кластеров MySQL.\
  2018 Октябрь 22 06:51 UTC - кластера завершили восстановление из резервных копий в одном ЦОД и начали репликацию новых данных в другой ЦОД.\
  2018 Октябрь 22 07:46 UTC - опубликована запись в блоге, для предоставления больше информации об инцинденте.\
  2018 Октябрь 22 11:12 UTC - основные БД восстановлены.\
  2018 Октябрь 22 13:15 UTС - выделены дополнительные реплики для MySQL в общедоступном облаке.\
  2018 Октябрь 22 16:24 UTC - реплики синхронизированы, устранены проблемы с задержкой и доступностью.\
  2018 Октябрь 22 16:45 UTC - начат процесс балансировки возросшей нагрузки.\
  2018 Октябрь 22 23:03 UTC - целостность и правильная работа всех систем восстановлена.

**Последующие действия:** В настоящее время проводиться анализ двоичных журналы MySQL и определение, какие записи могут быть автоматически согласованы, а какие потребуют взаимодействия с пользователями.
